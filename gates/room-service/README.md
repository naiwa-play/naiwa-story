# 双人好友房间

网页继续由 GitHub Pages 托管。此目录是独立的临时房间服务，负责房间码、准备开局、消息转发和 20 秒重连；战斗由房主计算。最多两人，无数据库、无账号登录、无公网排行榜。游戏币和手册保存在各自浏览器。

**当前状态：本地房间、双人选卡与战斗已经接通；正式站尚未配置云端服务地址。** `../rooms-config.js` 中的 `ROOM_SERVER` 为空时，正式站会明确提示尚未接通，不会建立假房间。

## 本地运行

需要 Node.js 22 或更高版本。在本目录执行：

```powershell
npm ci --ignore-scripts
npm test
npm start
```

默认监听 `127.0.0.1:5198`。前端本地预览使用 `127.0.0.1:5197` 或 `127.0.0.1:5191`，会自动连接本地房间服务。准备好两位玩家后，由房主开始。

## 云端部署

需要一个支持长期 WebSocket 连接的 Node.js 或容器托管账号；不需要用户的电脑常开。仓库自带 Dockerfile，容器入口为 `server.mjs`，健康检查路径为 `/health`。

- 服务必须提供公网 `wss://` 地址，前端 HTTPS 页面不能连接普通公网 `ws://`。
- 使用一个实例。房间保存在实例内存中，重启后房间结束；不要在未引入共享房间存储前开启多个副本。
- 容器绑定 `HOST=0.0.0.0`、`PORT=3000`；可按托管平台要求覆盖端口。
- `ALLOWED_ORIGINS` 为英文逗号分隔的网页来源，正式站为 `https://naiwa-play.github.io`。只填写来源，不带仓库路径。
- 单实例最多 50 个房间、100 条连接；消息大小与频率有限制，防止积压。可在服务端按实际预算调整。
- 部署成功后，把公网 WSS 地址填入 `../rooms-config.js` 的 `ROOM_SERVER`，更新该配置文件的版本查询串，并推送前端。浏览器中只放公开地址，不放任何云账号密钥。
- 验收应覆盖两台不同设备、不同网络、iPhone 内置浏览器、切后台重连与连续两局。国内可达性需要在实际部署地区和运营商网络上测试。

可使用支持 WebSocket 的腾讯云 CloudBase 容器托管等服务。正式开通前需确认用户账号、地区和费用预算，不默认购买或承诺永久免费。

## 双人规则

- 共同前进，各自左右移动、生命、武器、卡牌和能量模式独立。
- 共享击杀成长和拾取收益，各自选数字门。
- 两人各选一张成长卡，双方选好且所需模型就绪后继续。
- 岔路意见不同时轮流领路，两人获得同一条路线的事件效果。
- 倒地后，另一位伙伴靠近 1.35 米内并停留 2.5 秒可救援；两人同时倒地，或 20 秒内无人救援则结算。
- 任一方切后台或暂停时共同暂停。断网保留席位 20 秒，房主退出则房间结束，首版不迁移房主。
- 联机首版使用标准开局，不带永久商店强化，避免两人开局强度差异。单人玩法保持原有存档。
